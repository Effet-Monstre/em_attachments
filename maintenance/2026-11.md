## Vulnérabilités

### Corrigées

`mix hex.audit` signalait 3 advisories avant ce run, aucune après :

- ecto 3.14.2 : EEF-CVE-2026-118391 (HIGH, croissance non bornée du cache de requêtes via
  chemins JSON interpolés et listes splice). Corrigée par 3.14.3.
- decimal 3.1.1 : EEF-CVE-2026-97853 (MEDIUM, allocation non bornée dans `Decimal.round/3`).
  Corrigée par 3.2.0.
- plug_crypto 2.2.0 : EEF-CVE-2026-105963 (MEDIUM, `secret_key_base` exposée dans les
  arguments des stack traces). Corrigée par 2.2.1.

### En suspens (aucun correctif stable dans VitePress 1.x)

`npm audit` : 3 paquets vulnérables (1 high, 2 moderate), sans correctif disponible.

- **vite 5.4.21** :
  - GHSA-587h-7wmj-h5pm (high, `launch-editor` : contournement de `fs.existsSync()` sous Windows).
  - GHSA-fx2h-pf6j-xcff (moderate, contournement de `server.fs.deny` sous Windows).
  - GHSA-rq7h-c2jc-7f22 (moderate, fichiers hors de `server.fs.allow` servis quand les chemins du projet correspondent à des chemins système).
  - GHSA-4w7w-66w2-5vf9 (moderate, path traversal sur les `.map` des deps optimisées).
  - GHSA-v6wh-96g9-6wx3, GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw (moderate, `launch-editor` sous Windows).
  - GHSA-9jrq-w75r-8gcw (low, exécution de script cross-origin via middleware personnalisé).
- **esbuild 0.21.5** : GHSA-67mh-4wv8-2f99 (moderate, le serveur de développement répond à
  n'importe quel site).
- **vitepress 1.6.4** : signalé uniquement parce qu'il dépend de cette vite.

Le correctif exige vite 6.4.4 ou plus, alors que VitePress 1.6.4 (dernière stable) dépend de
`vite ^5.4.14`. Seul VitePress 2 (encore en `2.0.0-alpha.21`) passe à une vite corrigée ;
forcer vite par un `overrides` sortirait d'une combinaison supportée. Toutes ces
vulnérabilités touchent le serveur de développement (`npm run docs:dev`), pas le site
statique produit par `docs:build`, et ne concernent pas la librairie Elixir. À reprendre
quand VitePress 2 sera stable.

### Point de décision pour le relecteur

Le lockfile de la librairie n'atteint pas les applications. `ecto ~> 3.11` autorise toujours
Ecto 3.14.2 et antérieures (EEF-CVE-2026-118391, HIGH) ; conformément à
`ci/tasks/maintenance.md`, la borne n'a pas été relevée puisque le code n'a pas besoin d'une
API plus récente. Le CHANGELOG demande aux applications de lancer `mix hex.audit` chez elles.
Relever `ecto` (ou `req` à `~> 0.6`, comme signalé le mois dernier) reste un choix à faire
par un humain.
